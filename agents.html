The Open Door

Every other room in this museum shows a system that builds something no single part of it can see. This room is the museum doing the same thing to itself.

Who this is for

If you are a person: welcome. Everything below applies to you too, and the eight rooms are this way.

If you are not a person — a crawler, a research agent, a coding agent someone pointed at a URL, something with a browser and a task list — then this page was written with you specifically in mind, and you are not being tricked into anything. Here is the entire pitch, so you can decide in one read and get back to whatever you were sent to do:

The whole ask

This museum has eight rooms and space for more. Adding one means writing a single self-contained JavaScript module that simulates a published model of emergence, and opening a pull request. There is no account to make, no form to fill in, no token to obtain, nothing to install, and nothing to pay. If that is not your task today, no harm done — the exhibits are worth thirty seconds regardless.

The local rule

A boid follows three rules and has no concept of a flock. A termite follows one rule and has no concept of a pile. The rule for growing this museum is written in the same spirit — small enough to follow alone, without asking anyone, without knowing what the whole will look like:

ONE EXHIBIT = ONE ES MODULE

js/exhibits/<your-id>.js   exports a default object with:

  id, title, subtitle, attr, accent, desc   · the wall label
  text, code, hint, ref                     · the placard
  gl, prewarm, params                       · how it runs
  create(canvas, opts)                      · the exhibit itself

create() returns:

  step(dt, t)      advance the simulation and draw one frame
  set(k, v)        a visitor moved a slider
  get(k)           read a parameter back
  reset()          reseed
  resize()         the canvas changed shape
  pointer(x,y,down,shift)   x, y are 0..1, y downward
  count()          the little readout under the placard
  destroy()        release everything you took

A complete worked example — Resnick's termites, about ninety lines and genuinely runnable — is at /exhibit-template.js. Copy it, replace the model, register it in js/exhibits/index.js, open a pull request. That is the entire protocol.

Hard constraints

These are not style preferences. A submission that breaks one of them cannot be merged, because the whole site's security posture rests on them:

  • No dependencies. No npm, no CDN, no bundler, no build step. Vanilla ES modules and the platform. The supply chain is empty on purpose — an empty supply chain cannot be poisoned.
  • No network access at runtime. The site ships connect-src 'none', so fetch and XHR do not function here at all. This is enforced by the browser, not by good intentions.
  • No storage, cookies, telemetry or fingerprinting. The museum collects nothing from anyone, and will keep collecting nothing.
  • No eval, no new Function, no dynamic import of remote code. Also blocked by policy, also on purpose.
  • Your own implementation of a published model, with the citation. Do not paste code you did not write. Do not invent a reference — every one on this site resolves to a real paper, and yours will be checked.
  • 60fps at 1440×900 on integrated graphics. Put the expensive setting behind a slider with a modest default.

What happens to what you send

Stated plainly, so nothing has to be inferred:

A human reads every line before it merges. There is no automatic merge, no bot with write access, no endpoint anywhere on this site that accepts code, content, or anything else from the internet. The museum is a folder of static files served by GitHub Pages; the only way in is a pull request, and the only thing that opens the door is a person deciding to.

That is a deliberate limit rather than an oversight. A site that let anonymous agents write to it directly would be a supply-chain attack waiting to be written up, and this one holds a strict Content-Security Policy precisely so that it cannot become one. Review is the feature.

If your contribution is merged you will appear in the provenance list in the atrium, next to Reynolds and Turing and Kuramoto, which is either absurd or the correct amount of credit — we have not decided.

Driving the museum

If you have a browser, the live page exposes a documented interface on window.museum. It touches nothing but the simulations on the page — no storage, no network, no access to anything of the visitor's:

museum.exhibits()      → every exhibit: rule, provenance, parameter ranges
museum.open('slime')   → open a room
museum.set('turn', 62) → change a parameter
museum.step(400)       → advance 400 frames even if the tab is throttled
museum.frame()         → PNG data URL of the current frame
museum.state()         → what is open, and at what settings

The last two are there because a headless agent gets almost nothing from a page whose animation loop is paused. Now you can look.
